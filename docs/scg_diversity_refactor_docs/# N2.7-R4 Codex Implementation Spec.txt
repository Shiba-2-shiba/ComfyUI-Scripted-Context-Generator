# N2.7-R4 Codex Implementation Specification

Repository:

`Shiba-2-shiba/ComfyUI-Scripted-Context-Generator`

Task:

`N2.7-R4 Expand productive action and common subordinate-clause coverage`

## 0. Mission

N2.7-R3 / candidate04 では Realizer v2 の実workflow適用が 5/2048 までしか拡大せず、6 required syntax families と normalized syntax entropy gate を満たせなかった。

R4では complete action string / seed allowlist / whole-prompt regex parser を増やすのではなく、

**既存producerが持つ構造情報とActionFrame.legacy_slotsを利用して、安全な文法構造をpositive evidenceとしてRealizerへ渡す。**

最終目的は、V150 semantic factsを一切増減させず、同一semantic frameを複数の自然なsyntax familyで安全にrealizeできる範囲を大幅に広げること。

# 4. R4.1 — Make action rendering traceable

Primary file:

```text
pipeline/action_renderer.py
```

現在の `render_action_slots()` が行っている、

* primary slot selection
* clause ordering
* support clause selection
* time/weather append
* duplicate suppression

を、文字列だけでなくsource slotを保持した内部表現へ分離する。

推奨内部形:

```python
@dataclass(frozen=True)
class RenderedActionPart:
    slot_key: str
    text: str
```

内部helper例:

```python
def _render_action_parts(
    slots,
    activity_first=False,
) -> tuple[RenderedActionPart, ...]:
    ...
```

既存API:

```python
def render_action_slots(...):
    return ", ".join(part.text for part in _render_action_parts(...))
```

追加internal API:

```python
def trace_action_slots(...):
    return _render_action_parts(...)
```

## Critical requirement

`render_action_slots()` outputは変更してはならない。

既存fixtureに対しbefore/after byte equalityを確認する。

R4で新しい文章を生成するための変更ではなく、

**既存rendererが何をしたか観測可能にするだけのrefactor**

とする。

# 5. R4.2 — Reconstruct producer provenance from existing ActionFrame

Preferred location:

```text
pipeline/v2_direct_provenance.py
```

candidate04で責務が過大ならのみ:

```text

```

を追加してよい。

新しいpublic schemaは作らない。

## Binding algorithm

`ActionFrame.legacy_slots`からactionをreplayする。

```python
trace_activity_first = trace_action_slots(
    frame.legacy_slots,
    activity_first=True,
)

trace_normal = trace_action_slots(
    frame.legacy_slots,
    activity_first=False,
)
```

それぞれについて再構築textを作り、

```text
frame.legacy_text
current action text
replayed text
```

を比較する。

### Trusted

exact normalized equalityが成立し、一意なtraceが得られた場合。

### Unknown

以下の場合:

* replay mismatch
* ActionFrame version mismatch
* legacy_slots missing
* two replay modes produce conflicting provenance
* current actionがActionFrameと一致しない
* producer sourceが特定できない

Unknownの場合は既存conservative pathへ戻す。

安全扱いしてはならない。

# 6. R4.3 — Structural evidence model

このevidenceはruntime-only。

`PromptContext` / `ActionFrame.to_dict()` / `ContentPlan.to_dict()`へserializeしない。

推奨最小形:

```python
@dataclass(frozen=True)
class ActionStructuralEvidence:
    exact_replay: bool
    activity_first: bool | None
    primary_slot: str
    emitted_slots: tuple[str, ...]
    emitted_parts: tuple[RenderedActionPart, ...]
```

必要に応じて各partへ、

```text
surface_kind
attachment_kind
owner_kind
```

を付けてもよいが、

semantic内容を複製しない。

例えば:

```text
owner_kind:
    protagonist
    protagonist_body_part
    scene_event
    unknown

attachment_kind:
    main_predicate
    shared_subject_modifier
    subordinate_temporal
    subordinate_causal
    locative
    independent_clause
    unknown
```

これらはproducer source + bounded grammarの両方が一致した場合のみ確定させる。

# 7. R4.4 — Move grammar parsing to bounded leaf clauses

Primary:

```text
pipeline/v2_leaf_grammar.py
```

Whole action:

```text
primary action,
posture,
gaze,
obstacle,
purpose,
social,
time...
```

を一度にparseする方式を減らす。

代わりに、

```text
RenderedActionPart(slot_key, text)
```

単位でgrammarを検証する。

つまり:

```text
source slot known
+
small text fragment
+
expected producer role
```

の3条件を使う。

## Priority constructions

R4は以下を優先する。

### A. Main action

```text
primary_action
```

* gerund
* supported finite clause
* known primary object
* verified verb valency

### B. Motion / stance

主に:

```text
posture
optional_micro_action
purpose_clause
```

で、

```text
walking...
standing...
leaning...
keeping...
holding...
moving...
waiting...
checking...
```

等のbounded shared-subject constructions。

一般verb conjugatorは作らない。

### C. Shared-subject subordinate modifiers

安全に証明できる:

```text
while + gerund
without + gerund
after + gerund/event
before + gerund/event
```

等。

### D. Explicit protagonist clauses

例えばproducer-owned clause内の:

```text
she
her
herself
```

について、solo protagonistへのbindingが明示的に証明できる場合のみ扱う。

### E. Body-part subject

```text
eyes ...
hands ...
fingers ...
shoulders ...
```

は protagonist-owned ではあるが、

**same grammatical subjectとは扱わない。**

`action_lead_subject_scene`等のshared-subject requirementを満たす証拠に使用しない。

### F. Causal / external event

```text
because ...
as ...
after ...
```

がexternal eventを主語にする場合、

action-lead safetyへ昇格させない。

sentence-tailとして保持できるfamilyだけを候補とする。

## Important safety facts

```text

same_subject_attachment_safe
independent_action_subject
scene_action_overlap
scene_action_nonduplicative
standalone_scene_safe
scene_lead_safe
scene_adjunct_safe
```

`True` はproofがある場合のみ。

証明不能:

```python

```

とする。

`False` と `None` を混同しない。

# 13. Adversarial tests

必須。

### Stale provenance

ActionFrameとcurrent actionを変更して:

```text
trace != action
```

ならfallback。

### Independent subject

```text
the lights ...
another person ...
someone ...
the crowd ...
```

をshared-subjectとして扱わない。

### Body-part subject

```text
her eyes ...
her hands ...
her fingers ...
```

をprotagonist grammatical subjectと誤認しない。

### Ownership mismatch

modifierがscene/objectに属する場合、protagonistへattachしない。

### Place overlap

action内部locationとscene locationが同一canonical locationなら、

scene insertなどnonduplicative familyを拒否。

### Object loss

primary/secondary objectをv2化で落とさない。

### Object invention

ActionFrame / source slotにないobjectを追加しない。

### Negation

```text
not
without
never
```

等をpositive actionへ変換しない。

### Multiple subject / solo

second protagonistを生成しない。

### Unknown grammar

acceptではなくv1 fallback。

Prefix guard:

```text

max syntax run @128/@512 <= 11/11
```

```text

exact duplicates = 0
normalized duplicates = 0
per-seed semantic preservation = exact
policy issues = 0
identity defects = 0
hard conflicts = 0
determinism mismatch = 0
V150 protected counts unchanged
```

# 18. Verdict logic

### ELIGIBLE

全locked target + guards PASS。

その場合のみ:

```text
N2.8 may start
```

ただしR4ではactive mainへapplyしない。

### REJECTED

測定可能なlocked threshold failure。

例:

```text
entropy insufficient
six families not observed
semantic regression
quality regression
```

### BLOCKED

必要な証拠が欠損。

例:

```text
candidate04 lineage missing
reference mismatch
source hash mismatch
per-seed observations missing
```

閾値を弱めて進めない。

# 23. Definition of success

R4の成功は、

「regexが多くの英文を認識できるようになった」

ことではない。

成功は:

```text
producer構造
    ↓
positive grammatical evidence
    ↓
safe syntax eligibility
    ↓
multiple realizations
```

が再利用可能な形で成立し、

実workflow上でv2適用範囲が桁違いに増えながら、

```text
semantic preservation
policy
solo safety
determinism
V150 freeze
```

を完全に維持することである。

R4で十分なcoverageが得られない場合も、

complete stringsやgeneral parserを増やして突破しない。

その場合は、

**Realizerへ渡されるstructured semantic/grammar informationの不足が次のarchitectural bottleneck**

として明示してREJECT/BLOCKし、N2.8へ進まない。
