## Implemented result

`pipeline/family_capabilities.py` owns all new family authorization. It validates
the current evidence, reconstructs the source ContentPlan, checks the authoritative
catalog and binds each FamilyProof to its input, plan, catalog, constructor and
concrete-plan hashes. Construction recomputes the proof and compares its full
typed/canonical value. Caller-supplied labels, booleans, matching digests or mutable
ContentPlan fields cannot replace the current proof.

The common engine reuses existing profile, selected clothing, action and Scene
materializers. Clothing construction uses the already bound trace instead of
searching other packs. A single preparation is reused across all six family
proofs. New safety decisions do not use direct_binding_families or its three-family
ceiling. The legacy path retains that compatibility rule unchanged.

Scene relocation uses the existing producer-owned relative constructor, with the
predicate attached immediately after the gallery/interior head. Temporal/adorned
or unknown movements remain blocked. Owned-finite template wrappers only support
the existing standalone form. Standalone direct scenes retain their existing
constituent construction and documented overlap exception. Every other family
requires known non-overlap. Action-leading additionally requires protagonist
control for every action/garnish atom; body ownership does not supply that control.

ActionFrame is independently reconstructed using the producer's action_verb,
sorted object flags and from_slots projection. It is compared with the supplied
frame and available received frame; semantic metadata is never overwritten with
grammar-derived nouns. In particular clipboard remains an empty primary_object
under the existing semantic extractor even though the English action names it.
The output still retains the clipboard text.

Selector and realizer have explicit opt-in arguments and delegate to the common
engine. They reject mixed legacy/common authorization arguments. The successful
six-layout formatter is shared with the old path; ordinary Builder selection,
debug, fallback, punctuation and public serialization remain unchanged.
Transform rule IDs and source-atom-to-clause mappings accompany accepted proofs.

## Six-family evidence and its limits

All six families prove, construct and render in the labelled RECOMBINATION
fixtures. Tests inspect actual word/clause order and sentence count, preserved
appearance/clothing/action/mood, owned room wrappers and gallery sibling
references. Missing producers, unknown grammar, body/external action subjects,
unknown overlap, stale or forged proof/catalog/frame inputs are negative cases.

The same engine was independently measured over512 untouched real-graph inputs:
3,072 seed-family rows, with common eligible0 and common forced-v2 0 for every
family. This is not six-family runtime reachability. Ordinary compatibility
execution remains9/512 v2 across3 families and4 structures including fallback.
The new engine is not connected to ordinary selection in this task.

Common diagnostic blockers include unknown Scene502, Action500, Garnish447,
Clothing source410, template topology304 and Subject269. Counts overlap and must
not be added. The preceding R43-06 common-component audit found4 inputs blocked
only by Garnish; this remains a useful bounded starting point, not a promise of
family eligibility. R43-08 must address received-input reconstruction and prove
each family on unmodified real inputs before claiming coverage or development PASS.
